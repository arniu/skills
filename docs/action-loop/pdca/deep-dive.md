# PDCA — 深度解析

## 缘起与理论渊源

PDCA 循环由 Walter Shewhart 在 1930 年代提出（最初叫"统计控制循环"），后经 W. Edwards Deming 推广，成为全面质量管理和丰田生产体系的核心工具。

Deming 的版本其实叫 **PDSA**（Plan-Do-Study-Act），他认为"Study"比"Check"更准确——不仅是检查结果，更是研究过程，从中学习。日本企业把 PDCA 融入日常管理，发展出一套极为精细的操作方法（包括"5W 根因分析"、"A3 报告"等配套工具）。

有趣的是，PDCA 和**科学方法**是同构的：

| 科学方法 | PDCA  |
| -------- | ----- |
| 提出假设 | Plan  |
| 进行实验 | Do    |
| 分析数据 | Check |
| 形成理论 | Act   |

这意味着 PDCA 本质上是一种"用科学方法管理自己"的能力。

## 核心框架详解

### PDCA 的关键是 C（Check）

大多数执行者把精力放在 P 和 D（计划和执行），但 C 才是 PDCA 真正的价值所在。

**Check 的核心是"对比"**：实际结果 vs 计划目标。但这里有一个重要区分：

| 对比类型 | 问题                 | 作用             |
| -------- | -------------------- | ---------------- |
| 结果偏差 | 完成度多少？         | 量化的差距认知   |
| 过程偏差 | 在哪一步偏离的？     | 找到具体的断裂点 |
| 假设偏差 | 计划时的假设错了吗？ | 最深层的学习     |

大多数人只做了"结果偏差"（完成了 80%），跳过了"过程偏差"（第 3 天开始下滑）和"假设偏差"（我以为每天有 1 小时，但实际上只有 30 分钟）。后两者才是推动改进的关键。

### PDCA 的速度

PDCA 循环的速度决定了学习速度：

- **快循环**（每日）：适合微调执行方式
- **中循环**（每周）：适合 Action Loop 的标准节奏，调整目标和策略
- **慢循环**（每月/每季）：适合审视方向和大的策略假设

三个速度并存：每天的 PDCA 维持执行质量，每周的 PDCA 优化策略，每季度的 PDCA 审视方向。

### PDCA 的陷阱：没有 A 的 PDCA

最常见的 PDCA 失败模式是**永远在 P-D-C，从不真正 A**。原因：A 需要承认之前的计划有误，这让人不舒服。结果就是每周围绕同样的问题打转，永远在"分析"但从不"改变"。

**检查你是否真的做了 A**：翻出上周的复盘记录，如果这周的 Plan 和上周没有实质性区别，那你跳过了 A。

## 变体与进阶用法

### PDSA（Plan-Do-Study-Act）

Deming 本人的版本。"Study"不仅检查结果（Check），还研究过程和数据中的模式，理解"为什么会这样"。更适合复杂场景，其中因果关系不明确。

### OPDCA（Observation-PDCA）

在 Plan 之前加一个 **Observation（观察）** 阶段：收集数据、了解现状再制定计划。适合进入一个全新的领域，或者之前的复盘发现"我们对现状的理解有偏差"的场景。

### 团队 PDCA

团队复盘容易变成"谁做对了/谁做错了"。好用的格式：

1. 每人写自己的 C（Check）— 匿名
2. 汇总共识：哪些是团队层面的问题
3. 集体讨论 A：谁做什么调整

### 可视化 PDCA

用一个物理看板或数字看板：

- 把每周的 PDCA 写在一张卡片上
- 积攒到一个季度后，回头看整个变化轨迹
- 特别关注"反复出现的同一个问题"——说明 A 没有真正执行

## 与其他模型的对比与配合

### PDCA vs 复盘四步法

传统的"复盘四步法"（回顾目标→评估结果→分析原因→总结规律）与 PDCA 高度同构。区别在于 PDCA 强调**循环属性**——每次 A 的输出是下一次 P 的输入，而复盘四步法可能被视为一次性行为。

### PDCA vs KPT

KPT（Keep-Problem-Try）是 PDCA 的轻量版本，适合日/周级别的快速复盘：

- Keep（继续做）→ PDCA 的"好的行为"
- Problem（问题）→ PDCA 的"偏差"
- Try（尝试）→ PDCA 的 A

在 Action Loop 中，KPT 适合每日站会式的快速回顾，PDCA 适合周度的深度复盘。

### PDCA 与 Action Loop 中其他模型的关系

PDCA 的 A 阶段可能触发以下调整：

- 如果方向错了 → 回到"选方向"重新做黄金圈
- 如果计划太紧 → 回到"定计划"调整 SMART
- 如果障碍预估不准 → 回到"破障碍"更新 WOOP
- 如果执行不到位 → 回到"日执行"缩小微习惯

**判断路径**：如果连续两周同一问题没改善，说明当前的调整策略（A）无效，需要升级到更上游的环节调整。

## 多领域案例

### 案例一：个人学习计划（个人）

**P**：每天 1 小时学英语，每周完成 3 个单元
**D**：周一学了 45 分钟，周二到周四没学，周五 2 小时补
**C**：完成率 30%。原因：1 小时太大，加班后不想动
**A**：改为每天 15 分钟 + 周末 1 次集中复习。微习惯调整：从"学 1 小时"改为"打开 App 看一眼"

### 案例二：团队迭代改进（团队）

**背景**：一个开发团队发现每次上线都会延期，决定用 PDCA 改进。

**第一轮**：

- P：上线前 3 天代码冻结
- D：冻结了，但需求还是往里加
- C：冻结没有执行机制，PM 说"加一个不会影响"
- A：冻结期间代码合并需要 CI 管理员审批

**第二轮**：

- P：Code freeze + 管理员审批
- D：没有新需求加进去了，但 CI 跑测试花了 2 小时
- C：冻结有效，但部署时间太长
- A：优化 CI 流程，并行测试

结论：每轮 PDCA 解决一个问题，同时暴露下一个问题。**这不是失败——这是 PDCA 的正常工作方式。**

### 案例三：内容创作节奏（个人品牌）

**背景**：独立开发者每月产出 1 篇文章，想提升到每周 1 篇。

**P**：每周输出 1 篇 2000 字技术文章
**D**：第 1 周完成，第 2 周写了一半卡住，第 3 周补完
**C**：2000 字太长，写一半容易卡在"感觉不够好"
**A**：改为每周 1 篇 800-1000 字，不接受"不够好"的卡顿，写完即发

## 常见误区深度剖析

**1. 用 PDCA 逃避真正的决策**

"A 阶段"有时变成了"继续观察"。当你写"下周继续观察"的时候，你实际上跳过了 A。**连续两次 Check 同样的问题，必须做出改变。** 哪怕改变方向是错的——试错比不试有效。

**2. P 太模糊导致 C 无法评估**

"本周努力提升写作" → 无法 Check（什么叫"努力了"？）。**P 的清晰度直接决定 C 的质量。** 这就是为什么 Action Loop 中"定计划"环节用 SMART——SMART 写得好，PDCA 才有可检验的基准。

**3. C 阶段的"二元思维"**

Check 不是"完成了/没完成"的二选一。即使完成率只有 30%，也要问：那 30% 是怎么做到的？**好的复盘，一半时间花在"做得好的为什么不复制"上。**

**4. 只复别人的盘，不复自己的盘**

PDCA 最强大的用法是用来管理自己。团队的 PDCA 流程可以很完善，但如果每个人不给自己做 PDCA（"我这周哪件事的假设错了？"），改进只是组织层面的，不是个人层面的。
