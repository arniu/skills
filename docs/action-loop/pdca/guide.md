# PDCA — 实操指南

## 概述

复盘是 Action Loop 的"校正环节"。没有复盘，你只是在重复做同样的事，不知道哪些有效哪些无效。

PDCA 是丰田生产体系的核心工具，也是精益管理的基石。它不是一个"检查作业"的环节——它是一个**学习机制**：通过结构化的回顾，把经验转化为下一次的改进。

## 核心概念

| 阶段      | 含义     | 重点                                         |
| --------- | -------- | -------------------------------------------- |
| **Plan**  | 回顾目标 | 上周的计划是什么？SMART 目标是什么？         |
| **Do**    | 回顾执行 | 实际做了什么？完成了多少？                   |
| **Check** | 对比分析 | 差距在哪？原因是什么？                       |
| **Act**   | 改进措施 | 下周怎么调整？继续什么？停止什么？开始什么？ |

PDCA 的关键不是 P 也不是 D，而是 **C（Check）**。大多数人的"复盘"只做到了 D（我做了这些事），跳过了 C（我的假设哪里错了），就急着进入 A（下周做更多）。

## 操作步骤

### 第一步：回顾目标（Plan）

- 翻开上周定的 SMART 目标
- 列出计划中要做的事

### 第二步：回顾执行（Do）

- 诚实记录实际完成情况
- 完成了多少？哪几天断掉了？完成率多少？

### 第三步：对比分析（Check）

问三个问题：

1. **做的好的**：这周哪件事推进得很顺利？为什么？——好的原因值得复制
2. **有偏差的**：哪件事没按计划走？偏差在哪一步发生的？
3. **根因是什么**：不是"我没时间"，而是"什么占用了时间"或"什么让我不想做"

### 第四步：调整行动（Act）

根据 Check 的结论，输出下周的调整：

- **继续做**（Continue）：上周有效的行为
- **停止做**（Stop）：上周无效或浪费时间的事
- **开始做**（Start）：根据根因分析推出的新策略

把 Act 输出为新的 SMART 目标，进入下一轮循环。

## 真实案例

**背景**：阿杰的 Action Loop 跑了一周。

| 环节   | 计划内容               | 实际执行                 |
| ------ | ---------------------- | ------------------------ |
| 选方向 | 方向是"提升技术影响力" | 方向清晰                 |
| 定计划 | 每周 2 篇技术文章      | 只写了 1 篇              |
| 破障碍 | WOOP：没时间就写短篇   | 障碍不是时间，是完美主义 |
| 日执行 | 每天写 100 字          | 做到了 4 天              |

**Check 分析**：

- 好的：每天 100 字在第 4 天开始自动运行
- 偏差：目标 2 篇实际只写了 1 篇
- 根因：不是没时间，是写了不敢发，花太多时间修改

**Act 调整**：

- 继续做：每天写 100 字
- 停止做：写到完美才发
- 开始做：写完后不修改直接发，接受"不完美"

## 常见误区

1. **复盘变成流水账**
   "周一做了 A，周二做了 B…"——这是日志，不是复盘。复盘的核心是 C（分析），不是 D（记录）。

2. **只看结果不看过程**
   完成率 80%，就只盯着没完成的 20% 看。但完成的那 80% 有什么经验？哪些做得顺的可以复制？

3. **Act 太模糊**
   "下周要更努力"——不是可执行的 Act。"下周把写作时间从晚上移到早上"才是。

4. **做得不顺就全盘否定**
   一周没执行好，就觉得整个方向错了。先检查动作层面的问题（微习惯大小、WOOP 障碍找得对不对），再怀疑方向。

## 与循环中其他模型的关系

PDCA 检查的内容包括上游各环节的执行情况：

- 方向选对了吗？（选方向）
- 计划合理吗？（定计划）
- 障碍预判准了吗？（破障碍）
- 微习惯合适吗？（日执行）

Check 发现的根源问题可能指向任一环节——Act 就是调整该环节的输入。
