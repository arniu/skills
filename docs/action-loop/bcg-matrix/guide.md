# 波士顿矩阵 — 实操指南

## 概述

波士顿矩阵解决一个经典问题：**资源有限，选项太多，该投哪个？**

它由波士顿咨询集团（BCG）在 1970 年提出，最初用于企业产品组合管理。核心思想是：用"增长空间"和"竞争优势"两个维度把选项分为四类，不同类别采用不同策略。

## 核心概念

两个维度：

- **增长空间**（市场增长率）：这件事未来还有多大潜力？空间大还是小？
- **竞争优势**（相对市场份额）：你在这件事上相比别人有多强？优势大还是小？

四类象限：

| 象限        | 增长 | 优势 | 策略                       |
| ----------- | :--: | :--: | -------------------------- |
| ⭐ **明星** |  高  |  高  | 重点投入——这是你的未来     |
| 🐄 **金牛** |  低  |  高  | 收割利润——别过多投入       |
| ❓ **问题** |  高  |  低  | 选 1-2 个突破，其余暂缓    |
| 💀 **瘦狗** |  低  |  低  | 果断放弃，或少到不消耗精力 |

关键原则：**明星养起来会变成金牛，问题是明天的明星或瘦狗——投入之前先判断清楚。**

## 操作步骤

### 第一步：列出候选选项

把你在考虑的所有选项写下来。至少 3 个，不超过 8 个。

### 第二步：评估增长空间

对每个选项问：这个方向的成长空间大还是小？

判断依据：

- 这个领域本身还在增长吗？
- 现在入局还有时间窗口吗？
- 用**最坏情况假设**检验：如果增长很慢，我还愿意做吗？如果答案是"会"，说明动机来自 Why 而非增长。

### 第三步：评估竞争优势

对每个选项问：我在这件事上的优势是大还是小？

区分"我以为的优势"和"真实的优势"：

- 真实优势有外部验证——有人为你的能力付过费、你的产出被认可过
- 我以为的优势往往是一厢情愿

### 第四步：分类并决策

把每个选项放进对应的象限：

| 象限    | 决策         |
| ------- | ------------ |
| ⭐ 明星 | 优先投入     |
| 🐄 金牛 | 维持，不追加 |
| ❓ 问题 | 只选一个攻克 |
| 💀 瘦狗 | 划掉         |

## 真实案例

**背景**：一名工程师想在工作之外做自己的事，选项有：写技术博客、做 SaaS 产品、接外包、做开源项目。

**评估**：

| 选项    | 增长 |  优势  |  象限   | 决策     |
| ------- | :--: | :----: | :-----: | -------- |
| 写博客  |  高  | 有基础 | ⭐ 明星 | 投入     |
| 做 SaaS |  高  |   零   | ❓ 问题 | 远期目标 |
| 接外包  |  低  |   强   | 💀 瘦狗 | 放弃     |
| 开源    |  中  |   弱   | ❓ 问题 | 暂缓     |

**决策**：集中精力写博客。SaaS 等有明确方向后再启动。

## 常见误区

1. **把喜欢的当明星**
   高增长是客观判断，不是主观愿望。确认偏误让我们倾向于把"我想做的"标为明星。用最坏情况假设来校准。

2. **舍不得放弃瘦狗**
   "已经花了那么多时间"——沉没成本不是决策依据。

3. **两个维度判断太绝对**
   波士顿矩阵只有高/低两档，适合快速筛选。需要更精细的判断可以升级到 GE-McKinsey 九宫格（三档）。

4. **忘了定期重新评估**
   增长和优势都是动态的。上周的明星可能这周变成了问题。

## 与循环中其他模型的关系

波士顿矩阵承接黄金圈的输出——黄金圈找到"想做的"，波士顿矩阵判断"该做的"。筛选结果进入定计划环节用 SMART 拆解。
